今年最后一场 .NET 活动，我去了。想在阿德莱德找一个技术上真正有深度的聚会，这里是独一份。

第一次去的时候，内容技术含量太高，我整个人都懵了。不过就算听不懂也没关系，去个两三次，你会发现反复出现的主题都差不多，慢慢就能跟上了 :)。当然，最近的主角毫无疑问是 AI。

我平时解决问题更倾向于从用户体验出发，而不是从技术出发（当然，我也不否认自己骨子里有工程师思维）。但在这里，我可以毫无负担地聊技术，也能听到真正把技术用到实处的人分享他们的第一手经验。

也就是说，这场聚会是最高水准的，来的都是货真价实的工程师。（光是 Microsoft MVP 就有三位在场。Wow）除此之外，带团队的负责人和各路相关的利益方也会来，所以我有机会和各种不同背景的人聊天。

![阿德莱德 .NET 聚会上正在听演讲的参会者](./img_7611.avif)

举几个例子：

- 经营企业软件开发与咨询公司的 CEO
- 自由职业者
- 辞掉稳定高薪的工作去创业的人
- 做国防领域开发的人
- 学生和初级开发者
- 训练和开发 AI 模型的人
- 一直坚持举办 .NET、DDD Adelaide 这类本地社区活动的阿德莱德组织者们

就这样，我见到了各式各样的人。<br/>
说实话，除了钱以外，还有什么比这更能给开发者的东西吗？当然，免费的达美乐披萨除外。<br/>
我没吃晚饭，所以披萨吃得特别香，可惜忘了拍照。感谢提供披萨的 Simon、Encode Talent，还有赞助商（GUESTPIX）😋

这次聚会我特别留意的，是软件开发领域里开发者对 AI 的看法正在发生什么变化，以及这种变化实际带来的影响。

项目数量似乎越来越多，而对人力的需求却在减少。另外我也格外留心去听：我们工程师对好的设计那份执着和自豪，到底该怎么转化成客户也能真切感受到价值的东西。换个说法，就像 Richard P. Gabriel 那样，在他的 [Worse is Better](https://dreamsongs.com/WorseIsBetter.html) 和 [Worse is Better is Worse](https://dreamsongs.com/Files/worse-is-worse.pdf) 之间，我也快快乐乐地迷失了方向……哈哈。

啊对了，还有一段演讲中的问答让我印象很深。另一位软件工程师提出，AI 生成代码的审查成本实在太高，在实际工作中真的能提高效率吗？<br/>
演讲结束后，我专门去找了这位工程师，聊了挺久。我的观点是：不管是编译器，还是 JVM、.NET Runtime 这样的运行时环境，甚至是电路层面的 CPU 实现，我们都得信任某个黑盒才能把开发工作推进下去。所以从某个层面来说，软件开发者这个职业本来就是在信任黑盒的基础上工作的，那 AI 提示词（prompting）从根本上说不也可以用同样的思路吗？我还提出了自己的看法：开发者对 AI prompting 的偏好，说到底与其说取决于 AI 的“智能”或“能力”本身（我曾经抱有的这个信念，在过去一年里被无情地打碎了），不如说取决于开发者的工作意图能不能和 AI 模型同步，也就是舒适度的问题。

没想到，这位工程师做过很多国防方向的项目，和我所处的领域完全不同。在关乎人命、安全要求极端严格的环境和条件下，对系统了解到近乎过分的程度，反而是加分项。这次对话之后，我认真反思了自己的开发环境和技术栈。

- 我主要做 Web 开发。
- 我写的代码主要依赖浏览器或运行时（Java 或 C#）。JVM 和 .NET Runtime 简直像魔法一样，会根据执行环境自动优化到接近原生编译的水平（甚至更快）。
- 开发市场的主体是 Web，也许正因如此，从优化到编译检查再到类型检查，开发工具友好得离谱。不管我想搞砸什么，到处都张着安全网。
- AI 模型恰恰擅长这类工作。看过《钢铁侠 1》吧？托尼对贾维斯说“照这个样子把战衣做出来”，结果就真的做出来了。至少在数字世界里，我们早就达到甚至超越了那个境界。
- Web 开发真正复杂的部分，说到底还是数据库。我最近几乎是随便看一眼代码就提交了，但只要涉及实体和数据库的变更，我还是会审查两三遍。代码上线后还能改，可数据结构一旦成形，想改就真的很麻烦。只要我脑子里清楚地装着数据关系和结构，代码写得再烂也没关系，能编译通过，之后就能修（前提是没把结构搞得乱七八糟）。

总之，我们聊了很久。聊到最后说起大学学的东西，很自然地问到毕业多久了。我早知道对方经验比我多，可没想到他已经毕业 20 年了..！（我嘛，才 2 年。）<br/>
嗯……来到一个可以尽情聊 IT 和开发者经历的地方，我这个兴奋过头的两年经验开发者，说了一大堆自己的想法，对方还认真听完了，我一下子特别感激。

![.NET 聚会上介绍 DDD Adelaide 2026 活动](./img_7607.avif)

顺便说一句，DDD 我无条件推荐。它每年在阿德莱德举办，是开发者的圣诞节。

所以这次聚会给我的感悟是感恩。

- 那些为开发者打造工具的开发者，是他们营造了让我的代码尽情撒欢的环境。再直接一点，就是所有到场的 MS MVP 贡献者们。
- 搭建起这些交流聚会和场所的社区聚会组织者们。
- 不论资历深浅，都愿意倾听并询问我的感受和想法的资深工程师们。
- 让我在开发的森林里没头没脑地撒欢奔跑的 AI，以及每月只要 20 美元就能实现这一切的 Codex。（它不只是帮我写代码，在（至少是逻辑层面的）所有疑问上，我都获得了解放。）
- 让我在工作中积累了大量见解的公司。
- 最后，还要感谢让这些有趣的对话得以发生的酒吧，West Oak Hotel。（可惜，这里我也没拍照。）

接下来，我还会遇见什么呢？<br/>
在这里遇到的人当中，谁离我的未来最近？<br/>
很久以后，我会不会拥有一双能看清全局的工程师的眼睛？<br/>
又或者，我仍然会在开发的草丛里，开开心心、手忙脚乱地解着眼前的一道道谜题？
