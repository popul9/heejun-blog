얼마 전에 ['UI는 어렵다'](/ko/developer/ui-is-hard/)는 글을 올렸는데, 지인이 글을 보고 이런 걸 보여줬다.

![Worst UI Challenge의 메인 화면과 볼륨 조절 UI 출품작들](./worst-ui-challenge.avif)

[Worst UI Challenge](https://worst-ui-challenge.vercel.app/)

[레딧 채널](https://www.reddit.com/r/badUIbattles/)도 따로 있다고 한다. 

볼륨 조절하는 최악의 UI 를 만들어보는 챌린지라고한다.

재밌는데? UI는 어렵다고 불평할 생각만 해봤지, 일부러 망가뜨려볼 생각은 (적어도 최근엔) 해보질 못했다.

흠.. 늘 효율만 쫓으며 직진하던 내 뇌를 최대한 비효율적으로 돌려, 마치 뒤로 헤엄치는 물고기처럼, 비효율적인 UI를 만들어보자.

그래서 이 글은 이전 글의 패러독스이자 Richard P. Gabriel의 [Worse is Better is Worse](https://dreamsongs.com/Files/worse-is-worse.pdf)에 대한 오마주, 헌사, **UI is Hard is Easy**다. 하하 😆.


## 핵심 아이디어

공을 드래그해서 놓으면 찬다. 잘 맞춰보시길.. 하하.

오늘의 주제는 UX 망치기? 지만, 내 UX 가치관은 동일하게 적용한다. 사용자의 조작은 통제권을 가지도록 한다.
다른 표현으론, 통제할 수 없는 부분은 많을 수 있어도, 통제할 수 있는 건 하나만 줄게.

## Inspiration

영감은 올해 초 게임 박람회에서 본 **Pro Jank Footy**에서 얻었다. [여기](/ko/roamer/sage-2026/)에서 공유한 적 있다.

당시 공 움직임이 특이해서 개발자에게 어떻게 만든 거냐고 물어봤는데, 내부는 3D 엔진이고 유저에게 보이는 건 2D 필터를 씌운 거라고 한다. 이게 한동안 머릿속에 맴돌아서 언제 써먹어볼까 했는데, 드디어 써본다..ㅋ

![Steam의 Pro Jank Footy 소개와 게임 화면](./pro-jank-footy.avif)

이 게임은 얼마 전 Steam에서 정식 발매됐다. 캡처할 때 보니 평이 괜찮은 듯? 맥은 지원하지 않아서 일단 구매는 안 했다.

기사를 보니 애들레이드에 거주하는 한국인 아티스트 [hyemina](https://hyemina.com/about)라는 분도 작업에 참여했다고 해서 반가웠다. (나도 한국인임)

![hyemina studio의 개성 넘치는 작업들](./hyemina-studio.avif)

흥미로운 작업 많이 하시는 듯. 개성 넘치고 귀엽다.


![Codex 사용량과 사용 가능한 리셋 표시](./codex-usage.avif)
아무튼 이 작업으로 오늘 토큰 할당량은 다 털었다.
코덱스 리셋 너무 많이해준다. 사랑한다. Astra 토큰 소모 rate은 안 사랑한다.

![공을 내리꽂도록 조준한 모습과 SPIKE 표시](./spike-kick.avif)

원하면 공을 내리꽂아도 된다.

![카운트다운 아래에서 뛰어노는 강아지](./puppy-play.avif)
