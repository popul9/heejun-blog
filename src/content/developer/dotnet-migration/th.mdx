### รักข้างเดียว?
ผมเฝ้ามอง .NET มานานพอสมควร

- เป็นเฟรมเวิร์กที่นิยมที่สุดในออสเตรเลีย
- LINQ ที่ยืดหยุ่นและทรงพลังอย่างบ้าคลั่ง
- การคอมไพล์แบบ AOT native ที่เป็นธรรมชาติ
- ทำงานบน VM แบบเดียวกับ Java จึงมีการปรับแต่งตอนรันไทม์
- ความจริงที่ว่ากินหน่วยความจำและ CPU น้อยกว่า Spring อย่างเห็นได้ชัด
- ผมรู้กระทั่งว่าประสิทธิภาพสูงสุดยังเหนือกว่า Java ด้วยซ้ำ
- โดเมนของบล็อกนี้ก็คือ heejun dot net
- ผมถาม ChatGPT อยู่บ่อยๆ ว่า C# เทียบกับ Java แล้วให้ความรู้สึกยังไง
- แล้วก็เข้าร่วมคอมมูนิตี้ .NET ที่แอดิเลดอย่างสม่ำเสมอ (Spring Boot ไม่มีในแอดิเลด)
- ผมรู้แม้กระทั่งเรื่องเบื้องหลังการกำเนิดอันสกปรก? ของมัน สมัยที่ Microsoft ปล่อยยาพิษใส่ค่ายโอเพนซอร์สและวางแผนให้มันเป็นตัวสังหาร Java

### สถานการณ์เปลี่ยนไปแล้ว
ถึงผมจะมีตัวตนเป็นนักพัฒนา Java แต่ตอนนี้คือยุคของ LLM<br/>
การไม่มีประสบการณ์กับภาษาหรือเฟรมเวิร์กใดเฟรมเวิร์กหนึ่งจะเป็นข้อจำกัดตรงไหนล่ะ? โปรเจกต์ส่วนตัวน่ะ ถ้าเจ๋งก็ลงมือทำเลย! <br/>
สุดสัปดาห์ที่ผ่านมา ผมกับผู้ช่วยของผม Antigravity เริ่มย้ายแอปพลิเคชันแบ็กเอนด์ของ Anotherhome ที่เป็น SpringBoot เดิม

### น่าตื่นเต้น
อย่างที่พูดไว้ในโพสต์ก่อนหน้าเรื่อง <a href="https://heejun.net/ko/developer/language-picker/" target="_blank" rel="noopener noreferrer">ตัวเลือกภาษา</a> ผมชอบการทำ optimisation (เรื่องที่รู้สึกได้จริงหรือไม่นั้นเอาไว้ทีหลัง) Spring Boot ของผมคอมไพล์ด้วย GraalVM ใช้เวลาบน GitHub ถึง 45 นาที
![blog placeholder](./github-action.webp)
แถมยังต้องตั้งค่าสภาพแวดล้อมการคอมไพล์ให้ดีอีก ต้องจัดให้พอดีกับหน่วยความจำที่จัดสรรไว้ (ไม่ถึง 8Gb) แบบเฉียดฉิวถึงจะคอมไพล์ผ่าน แล้วยังต้องปรับจำนวนคอร์แบบขนานให้ตรงอีก<br/> ที่แย่ที่สุดคือต่อให้คอมไพล์สำเร็จมาอย่างยากลำบาก ตอนรันไทม์ก็ยังโยน error ออกมาบ่อยๆ (reflection) <br/>
พูดง่ายๆ คือจนกว่าจะลองรันก็ไม่รู้ว่าจะพังหรือเปล่า ในทางกลับกันได้ยินว่า .NET รองรับ AOT Native ในทุกส่วนนี้อย่างเป็นธรรมชาติ จะมีอะไรน่าตื่นเต้นไปกว่านี้อีก หิหิ
